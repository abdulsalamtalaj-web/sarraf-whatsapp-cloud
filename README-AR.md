# صرّاف — حزمة استضافة مستقلة تجريبية

هذه حزمة مصدر جاهزة للتهيئة والنشر، وليست خدمة منشورة أو إصدار تطبيق متصل بالخادم بعد.

## ما تم تجهيزه

- قارئ Node.js لقناتَي واتساب اللتين حددهما المستخدم فقط، دون إرسال رسائل.
- استخراج العملات والذهب النصي، مع فصل الشراء والمبيع وتوقيت النشرة عن وقت الجلب.
- حفظ آخر نشرة قديمة بعلامة قدم، ووقف القفزات الكبيرة غير المؤكدة.
- خدمة Render بخطة free صراحة في render.yaml.
- Worker وD1 على Cloudflare لتخزين الجلسة المشفرة وإتاحة الأسعار العامة.
- تشفير AES-256-GCM للجلسة؛ مفتاح التشفير يبقى في إعدادات Render ولا يوضع في الكود أو D1.
- قفل مؤقت يمنع نسختين من القارئ من استخدام الجلسة معاً.
- صفحة ربط واتساب محمية باسم admin وكلمة مرور مولدة في Render.
- مهمة مجدولة كل دقيقتين تطلب جلب النشرات من القارئ؛ /rates يقرأ آخر نتيجة مخزنة.

## ما لم يتم

- لم تُنشأ حسابات Render أو Cloudflare، ولم تُنشر خدمة.
- لم تُرفع أو تُنقل جلسة واتساب المحلية إلى أي طرف.
- لم يُنشأ مستودع GitHub جديد؛ مستودع صرّاف الأصلي لم يتغير.
- لم يُختبر بناء Docker لعدم توفر Docker في بيئة التنفيذ.
- اختبارات Cloudflare تستخدم SQLite محلياً لمحاكاة عقد D1 وليست إثباتاً للنشر على Cloudflare.
- ما زال التطبيق يحتاج ربط عنوان /rates الجديد وتعديل قراءة زوج أسعار الذهب. API الذهب يحفظ quotes_usd لكل عيار، ولا يفترض وزن الغرام إذا لم تصرح به النشرة.

## تسلسل النشر بعد تسجيل الدخول

1. إنشاء مستودع مستقل خاص من هذا المجلد، دون private أو أسرار أو جلسات أو node_modules.
2. من Cloudflare، إنشاء D1 باسم sarraf-whatsapp وتطبيق cloudflare/schema.sql، ثم وضع معرفها في wrangler.toml.
3. توليد STORE_TOKEN عشوائي قوي وحفظه كسر Worker. لا يُدرج في الكود.
4. نشر Worker على الخطة المجانية، وتسجيل عنوان HTTPS كقيمة STORE_URL في Render.
5. إنشاء خدمة Render من render.yaml بخطة free. STORE_TOKEN يطابق سر Worker؛ SESSION_KEY وADMIN_PASSWORD يولدان مرة واحدة ويُحفظان في إعدادات الخدمة. تغيير SESSION_KEY يفقد إمكانية فك الجلسة القديمة.
6. قبل نقل جلسة واتساب السحابية، التأكد من موافقة المستخدم على تخزينها لدى Render ونسختها المشفرة لدى Cloudflare. الأسهل ربط الرقم مباشرة من صفحة الإدارة المستضافة بدلاً من رفع ملفات الجهاز.
7. إيقاف القارئ المحلي الخاص بهذا المشروع قبل ربط جلسة القارئ المستضاف لتجنب جلسات اختبار متزامنة.
8. إضافة READER_URL في متغيرات Worker بعنوان خدمة Render. طلب POST /poll يستخدم STORE_TOKEN في ترويسة ولا يضعه في الرابط.
9. التحقق من استقبال نشرات القناتين، وحفظ الجلسة واستعادتها بعد إعادة التشغيل، وواجهة /rates، ثم إصدار APK معاينة مستقل متصل بها.

## حدود التشغيل المجاني

Render Free قابل للنوم وإعادة التشغيل وله حدود ساعات واستهلاك. لا يوجد ضمان تشغيل دائم أو عدم الحاجة لإعادة ربط واتساب. Cloudflare Free له حصص تشغيل وتخزين. لا يجب تفعيل خطط مدفوعة أو وسيلة دفع دون طلب المستخدم. قارئ واتساب غير رسمي ويحتاج صيانة عند تغير البروتوكول.

## الاختبارات

من المجلد الرئيسي:

    node --test reader/reader.test.mjs reader/gold.test.mjs reader/persistence.test.mjs cloudflare/worker.test.mjs

اجتازت 14 حالة اختبار، بما فيها التشفير وكشف العبث، منع تسريب الجلسة في API العام، قفل القارئ، وتصنيف قدم النشرات. تشغيل الخدمة الفعلي يحتاج حسابات الاستضافة وإعدادات الأسرار.

لا تحتوي هذه الحزمة على الجلسة المرتبطة أو كلمات مرور حقيقية.
